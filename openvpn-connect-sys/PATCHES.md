# Native source notes

The Git repository pins pristine upstream source as submodules:

- OpenVPN 3 Core 3.11.7 at `18edfae7e7fd8051c93bd4746ec69be91eb02dbb`;
- standalone Asio 1.24.0 at `147f7225a96d45a2807a64e443177f621844e51c`.

The submodules stay clean. `build.rs` copies only their required source trees
to `OUT_DIR/patched-native-source` and applies `patches/openvpn3.patch` and
`patches/asio.patch` with an in-process unified-diff applier. No Git or external
`patch` executable is used during a crate build. The same upstream files and
patches are embedded as ordinary files in the published `.crate` archive.

The OpenVPN compatibility patch provides optional paths that the upstream SWIG
build does not normally compile:

- Gremlin callbacks decay and forward move-only handlers correctly; TCP and
  UDP transports pass their concrete `io_context` and expose the Gremlin
  configuration consistently.
- The external transport headers forward-declare their framework type before
  logging headers are included, and the external transport configuration
  carries the Gremlin setting used by the custom Rust factory.
- Linux DCO selects Core's SITNL tunnel backend, which provides the interface
  creation/deletion operations used by `OvpnDcoClient`.

The Asio patch preserves OpenVPN Connect compatibility hooks for protected
sockets, Apple NAT64 resolution, Windows error messages, Linux route IDs, and
resolver result inspection.

The stable adapter in `src/bridge.cpp` also clears OpenSSL per-thread state at
the end of a connection. This is necessary when OpenVPN Core runs on a reusable
Tokio blocking-pool worker: otherwise OpenSSL 3 can retain a pointer to a freed
private `OSSL_LIB_CTX` until the worker thread exits.

All raw Rust declarations continue to be generated by bindgen from
`src/wrapper.h`; no generated binding file is edited manually.
